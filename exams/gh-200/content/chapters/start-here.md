# 開始使用：GH-200 四週備考指南

## 官方基準

本指南以 **GH-200: GitHub Actions** 的技能範圍組織內容，對應 **GitHub Actions** 認證。讀者應已熟悉 Git、repository、pull request 與 YAML；本書把重點放在每項 Actions 功能「在什麼事件下觸發、拿到哪個 commit 與權限、由誰能設定與治理」，以及工作流程失敗或被攻擊時該先檢查什麼。

教材於 2026-11-03 依官方 Study Guide 與 GitHub Docs 的功能頁面整理，來源網址與標題列在來源頁。這是本站自行整理，不代表經過官方或專家審訂。Study Guide 標示的技能範圍日期是 2026 年 1 月，頁面日期為 2026-02-04；官方在該頁的變更紀錄中寫明，這個考試在 2026 年 1 月有**大幅改版**（新增、移除與重新分組目標，且全部改寫），所以 2026 年以前的網路教材與題庫可能對不上。考試時間、語言、預約條件與最新範圍，請在報名前查閱[認證頁](https://learn.microsoft.com/en-us/credentials/certifications/github-actions/)與[Study Guide](https://learn.microsoft.com/en-us/credentials/certifications/resources/study-guides/gh-200)（GH200-CERT、GH200-SG）。

### 分清三種內容

**官方技能範圍**說明需要掌握的能力；**產品文件**描述功能在特定條件下的行為與限制；**本書案例與練習**用來訓練判斷，不是官方固定程序，也不是實際考題。Actions 的行為會依事件類型、分支、runner 種類、方案與組織政策而不同，所以讀每個功能時都要先問：「這個條件下它還成立嗎？」

各章每個小節末尾的來源說明寫明本節對照了哪些頁面；沒讀到或沒核對到的細節，會在該節明講，備考前請讀來源原文。

## 使用方式

第一次閱讀可依第一章到第五章建立完整流程，再讀整合章；查找概念時，直接搜尋 `workflow_dispatch`、matrix、reusable workflow、OIDC、`GITHUB_TOKEN` 等詞彙，進入對應小節。每個技能小節都保留判斷練習，先自己寫下答案再看解析。

### 全書貫穿案例

假設 Contoso 的訂單團隊維護 repository orders-api，用 GitHub Actions 建置、測試並部署。他們在不同作業系統與版本上跑矩陣測試，測試需要資料庫服務，部署步驟呼叫平台團隊維護的可重用工作流程，並向雲端供應商取得短期憑證；組織管理員要控制哪些 actions 可以使用、哪些 runner 可以接工作，以及 secrets 放在哪一層。

第一章分清如何觸發與設計工作流程；第二章處理讀懂與疑難排解；第三章撰寫與發佈自訂 actions；第四章在組織與企業層級治理；第五章處理安全與成本；整合章把一次部署從觸發到驗證串起來。

### 每次閱讀的實際產物

1. 選一個小節，先讀情境，寫下自己的下一步及理由。
2. 閱讀解析，指出原答案漏掉的條件；不只抄結論。
3. 在自己的 repository 寫一個最小的工作流程驗證該設定，記下實際看到的日誌或畫面。
4. 做對應練習題，記錄答錯原因，再回到教材補足因果關係。

28 天計畫是安排節奏的輔助，不是完成天數就代表學會。對熟悉的領域可以快速檢核；對尚無實作經驗的內容，保留時間在可拋棄的環境驗證。

### 在可拋棄的環境驗證

公開 repository 可以免費使用 GitHub-hosted runner、快取與成品，所以最省錢的練習方式，是建立一個專門練習用的公開 repository。組織與企業層級的功能（runner groups、組織層級的 actions 政策、IP 允許清單、組織範本）需要組織帳號與管理權限，個人 repository 無法完整驗證，這部分只能讀文件。

練習時不要使用任何真實的憑證或雲端帳號；測試 script injection 時，只在自己的練習 repository 用無害的字串，並避免讓別人的貢獻觸發它。

## 應考原則

先找題幹要達成的結果與限制，再比較選項是否真的解決那個問題。常見的限制詞是哪個事件觸發、預設分支或功能分支、組織或 repository 層級、事前或事後；看到某個功能名稱就選，卻沒確認它在題目的條件下是否成立，是最常見的失誤。

兩個方案都可行時，優先選擇官方文件明示的做法，不替題目增加未寫出的條件。數字題（天數、容量、上限）要連同它所指的對象一起記，例如 10 GB 是每個 repository 的快取預設上限，1 MiB 是每個步驟的摘要上限。

官方及格量尺分數不能直接換成固定答對率。本站設定的練習目標只是提醒，未經校準，不能預測正式考試通過。比數字更重要的是：每一題答錯，都能指出是哪個條件看漏了。

**暖身練習：** 同事說「我在功能分支改了 `schedule` 的 cron，已經好幾個小時都沒跑」。你最先確認什麼？

**解析：** 先確認該工作流程檔是否在預設分支。`schedule` 只在預設分支的最新 commit 上執行；功能分支上的修改不會被排程拿來執行。
